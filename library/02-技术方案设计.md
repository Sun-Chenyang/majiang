### 1.1 参考代码分析与复用策略（AR-Mahjong-Assistant-preview）

`library/参考代码/AR-Mahjong-Assistant-preview` 是一个 AR 眼镜麻将助手（Android Kotlin 客户端 + Python FastAPI 服务端 + YOLO 识别），**其牌理算法与本项目高度相关**，是核心移植蓝本：

| 参考文件 | 内容 | 我们的复用方式 |
|----------|------|----------------|
| `server/efficiency_engine.py`（597 行） | 牌效引擎：进张计算、最优切牌、鸣牌时机、摸打查表 | **算法架构整体移植为 Dart**（详见 §4） |
| `server/mahjong_state_tracker.py` | 对局状态跟踪、已见牌事件模型（弃牌 +1 / 碰 +3 / 杠 +4）、副露锁定 | 概念移植到"已见牌标记"（P1）与副露模型 |
| `server/performance_test.py`、`server/tests/` | 随机手牌模拟、静态定型手牌用例、性能基准 | 测试方法论移植（§8） |
| `MahjongMapper.kt`（历史参考） | 麻将 Unicode 字符（🀙🀔🀄）渲染牌面 | 备选渲染方案（见 §5.1） |
| YOLO 识别 / 语音 / AR 眼镜 / LLM 部分 | 图像识别与语音交互 | **不复用**（本项目为手动输入的单机工具） |

**关键架构收获（本方案据此升级）**：参考项目的核心是**向听数（shanten）+ 进张（ukeire）**框架，而非"是否听牌"的布尔判断：

- 向听数：-1=已胡，0=听牌，n=差 n 张有效牌进听——未听牌也能给出量化差距与改进方向；
- 进张：使向听数下降的所有牌及剩余张数——听牌时即"所听的牌"；
- 最优切牌排序键 `(向听数升序, 进张张数降序)`——本项目打牌建议沿用此排序。

**不复用其 Python 依赖**：参考项目向听数来自 pip 库 `mahjong`（日麻 34 种牌），Dart 无对应库，且卡五星需 21 种牌定制，故向听数算法按成熟公式自研移植（§4.2）。**不复用其番型判定**（日麻役种体系与卡五星完全不同，番型仍按规则文档自研）。

**必须适配的卡五星差异**：

| 差异点 | 参考项目（日麻） | 本项目（卡五星） |
|--------|------------------|------------------|
| 牌种数 | 34（万筒条 + 风箭） | **21**（筒、条 + 中发白） |
| 吃 | 支持 | **无吃**（鸣牌建议只留碰/杠） |
| 起手 | 13/14 张 | **庄家 14 张、闲家 13 张**起手 |
| 七对规则 | 4 张同牌只算 1 对 | **4 张同牌算 2 对**（龙七对），七对向听公式需调整 |
| 副露 | 需录入副露牌组（含锁定概念） | **不录入**：张数推断组数（§3.2），字牌副露可选标记（P1） |
| 番型 | 日麻役种 | 卡五星 14 番型自研（§4.4）

### 3.2 手牌状态（副露省录模式）

用户**只录入当前手中的暗牌，不录入已碰/杠出的牌**（PRD FR1.5，输入简化是第一优先级）。副露组数由张数自动推断；副露的具体牌只影响三元番型（中/发/白刻子可能在副露中），用可选的字牌标记补全。

```dart
class HandState {
  final Uint8List concealed;    // 长度 21 的暗牌计数（不含碰/杠出的牌）
  final Set<int> honorMelds;    // （P1，默认空）已碰/杠的字牌牌种 ⊆ {中(18), 发(19), 白(20)}
  int get count;                // 暗牌总数
  bool get isDrawPhase;         // count ≡ 2 (mod 3) → 待打（打牌建议态）；≡ 1 → 待摸（听牌判断态）
  int get meldCount;            // 推断副露组数：待摸态 (13−count)/3；待打态 (14−count)/3
  int seenCount(int t);         // 已见张数 = 暗牌[t] + honorMelds 含 t 时 +3（P1 加弃牌标记）
  int remainCount(int t);       // = 4 − seenCount(t)
}
```

**推断正确性**：胡牌结构固定为"4 面子 + 1 对"，待摸暗牌恒为 13 − 3×副露数，待打恒为 14 − 3×副露数；暗杠/补杠不破坏该 mod 3 循环（杠 4 张折算 1 个面子并补摸 1 张）。因此张数推断无歧义，向听数/进张/打牌建议均只需 `meldCount`，无需知道副露具体是什么牌。

**三元番型精度缺口**：小三元/大三元要求中/发/白为刻子（可能在副露中）。未标记 `honorMelds` 时仅按暗牌判定并在结果区提示"三元番型按暗牌计算"；标记后补全。这是省录模式的唯一精度损失，且只影响 ≥1 组副露且碰杠字牌的情形。

### 4.0 当前实现基线（engine.dart，v0.1）与 v0.2 目标差距

`core/engine.dart`（339 行）已实现**布尔版听牌框架**，是 v0.2 算法深化的起点：

| 能力 | 现状（v0.1） | v0.2 目标 | 差距 |
|---|---|---|---|

| 听牌/进张 | `waitsOf` / `advancesOf`（枚举 21 种加牌试判）✓ | 进张泛化（向听数下降的牌，任意向听数下成立） | 现实现等价于"加牌后 canWin/hasWait"，逻辑对但无法给出 n 向听 |

以下 §4.1–§4.8 为目标设计规格（v0.1 撰写，继续有效）。

### 4.1 胡牌判定与分解枚举（win.dart）

**函数签名**

```dart
class WinStructure {
  final int pair;              // 雀头牌种
  final List<Meld3> melds;     // 顺子/刻子（暗牌部分）
  final bool isSevenPairs;     // 七对形态
}
List<WinStructure> decompose(Uint8List c14);   // 全部分解；空 = 未胡
```

**算法**（计数数组上的标准回溯，规模极小无需查表优化）：

1. **七对检查**：无副露、14 张、所有计数为偶数 → 产出七对形态（含龙数统计：计数 = 4 的牌种数）。
2. **标准型回溯**：
   - 枚举雀头 t（`c[t] >= 2`），减 2；
   - `decomposeMelds`：找最小的不为 0 的牌种 t：
     - 若 `c[t] >= 3` → 尝试刻子（c[t] -= 3，递归）；
     - 若 t 属于筒/条且 `rank(t) <= 7` 且 `c[t+1] > 0 && c[t+2] > 0` → 尝试顺子；
     - 两者都失败 → 该分支剪掉；所有计数归零 → 记录一组分解。
   - **字牌（18-20）只可刻子/雀头，不可顺子**（编码上 `t>=18` 无 t+1/t+2 同花色意义，天然剪枝）。

**为什么枚举全部分解而非只判 true/false**：番型判定依赖具体分解——例如小三元要求中发白"2 刻 + 1 对"，同一手牌可能同时存在"小三元分解"与"非小三元分解"，听牌结果必须按分解分别算番，全部展示、标注最优。14 张牌的分解总数上限很小（实测几十个量级），性能无忧。

### 4.2 向听数计算（shanten.dart）★ 参考代码移植

向听数（shanten）：距听牌还差的有效进张数。**-1 = 已胡，0 = 听牌，n = n 向听**。这是听牌判断的泛化——未听牌时不再只回答"没听"，而是量化差距并支撑进张/切牌建议（移植自参考项目 `efficiency_engine.py` 所用 `mahjong` 库的算法框架，按 21 种牌重写）。

```dart
/// hand: 暗牌计数（不含副露）；melds: 副露（每个面子/杠折算已完成面子）
/// 返回 min(标准型向听数, 七对向听数)；七对仅在无副露时参与
int calculateShanten(Uint8List concealed, List<Meld> melds);
```

**标准型向听数**（经典公式，回溯求最优分解组合）：

```
向听数 = 8 − 2×面子数 − 搭子数对雀头的贡献（修正项）
约束：面子数 + 搭子数 ≤ 5；雀头（对子）可由搭子升级
```

实现采用回溯法枚举"面子（顺/刻）+ 搭子（对子/两面/嵌张）"的最优组合取最小值——复用 §4.1 的回溯框架（同一套"找最小非零牌种 → 尝试刻/顺/对/搭"的分支结构），规模同样极小。**字牌搭子只可以是刻子搭（对子）**，无两面/嵌张。

**七对向听数**（卡五星定制）：

```
七对向听数 = 6 − 对子数 + max(0, 7 − 种类数)
```

⚠️ **卡五星定制点**：`mahjong` 库按日麻规则 4 张同牌只算 1 对；卡五星的龙七对允许 **4 张同牌算 2 个对子**（龙七对/双龙/三龙的判定基础）。因此对子数统计为 `Σ min(count ÷ 2, 2)`。此差异同时影响七对向听数与番型判定（§4.4），是移植中最易踩坑处，必须专项测试。

**副露处理（省录模式）**：副露组数由暗牌张数推断（§3.2），折算为已完成面子数参与公式（面子数起点 = `meldCount`）；张数 < 13/14（即有副露）时七对分支返回 +∞。暗杠补摸不破坏 mod 3 循环，推断依然成立。

### 4.3 进张与听牌计算（ting.dart）

进张（ukeire）泛化定义：**使向听数下降的牌**。听牌（向听数 0）时，进张 = 胡牌张。

```dart
class UkeireResult {
  final int shanten;                  // 当前向听数
  final List<AcceptedTile> accepted;  // 全部进张
}
class AcceptedTile {
  final int tile;
  final int remain;                   // 剩余张数 = 4 − 已见
  final bool isWin;                   // 向听 0 时 = 胡牌张
  final List<WinWithFan>? wins;       // 仅胡牌张：每种可胡分解 + 番型评估
}
UkeireResult computeUkeire(HandState hand, WinContext ctx, RulesConfig cfg);
```

**算法**（移植参考项目 `_get_ukeire`）：对 21 种牌 t，若 `remainCount(t) > 0`：`c[t] += 1` → `calculateShanten` 下降 → t 为进张，记录剩余张数；向听数为 0 时对每个胡牌张调用 `decompose(c14)` 枚举全部分解并逐个做番型评估（§4.4）。

**复杂度**：21 次向听计算，每次为回溯枚举，总耗时 < 1ms（开发时以基准测试断言，见 §8）。

**兼容任意 3n+1 张**：进张判定只要求"加入一张后向听数下降"，因此 13 张（无副露）、10 张（1 副露）、7 张（2 副露）…统一适用，无需按张数分支。

### 4.4 番型判定（fan.dart）

FanScore evaluateFan({

**判定规则表**（对应规则文档第六章，含实现要点）：

| 番型 | 倍数 | 实现要点 |
|------|------|----------|
| 屁胡 | 1 | 基准；`cfg.pingHuSelfDrawOnly && !ctx.selfDraw` → 该分解不可胡（点炮胡需 ≥1 个其他番型） |
| 卡五星 | 2 | 固定（2026-08-16 裁决）：`winTile == 5筒/5条 && structure 存在以其为中间张的 456 顺子`（筒条同计卡张） |
| 杠上炮 | 2 | 纯情境 `ctx.gangPao`（供"打哪张会点杠上炮"提示，听牌器不判定他人听牌） |
| 杠上开花 | 2 | 纯情境 `ctx.afterGang && ctx.selfDraw` |
| 抢杠 | 2 | 纯情境 `ctx.robKong` |
| 小三元 | 4 | 中/发/白恰 2 刻 + 1 对（对 = 雀头）；**刻子含暗牌刻与 `honorMelds` 标记的副露刻**，未标记时仅按暗牌判定并提示 |
| 暗四归一 | 4 | `c14[t] == 4 && winTile == t && ctx.selfDraw`（3 张暗牌在手 + 摸第 4 张） |
| 七对 | 4 | `structure.isSevenPairs`；张数 < 13/14（有副露）则七对系全灭 |
| 大三元 | 8 | 中发白 3 刻（含 honorMelds 副露刻）；**不计小三元** |
| 龙七对 | 16 | 七对 + 暗牌中恰 1 种计数=4；**不计七对** |
| 三元七对 | 16 | 七对 + 中发白各为对子；不计七对（⚠️ 与小三元共存性做成配置，默认并存连乘） |
| 双龙七对 | 32 | 七对 + 恰 2 种计数=4；**不计七对、龙七对** |
| 三龙七对 | 64 | 七对 + 恰 3 种计数=4；**不计七对、龙七对、双龙七对** |

**互斥实现**：命中集合按番型优先级排序后，`excludes` 逐个吞并（如命中三龙七对则从集合移除七对/龙七对/双龙七对并在结果中记录"被不计"），`multiplier = Π 剩余项倍数`。

**多分解取最优**：同一 `winTile` 的每个分解各自得到 `FanScore`；结果按 `multiplier` 降序展示全部，标最优；同时按 `ctx` 过滤不可胡的分解（如屁胡点炮）。

### 4.5 打牌建议（advice.dart）

```dart
class DiscardOption {
  final int discard;                 // 建议打的牌种
  final int shanten;                 // 打后向听数
  final List<AcceptedTile> ukeire;   // 打后进张列表（听牌时 = 所听牌，P1 起含番型）
  final int totalRemain;             // Σ 进张剩余张数
  final int fanWeightedScore;        // P1：Σ(剩余张数 × 番倍数)
}
List<DiscardOption> rankDiscards(HandState h14, ...);
```

**算法**（移植参考项目 `calculate_best_discard`）：对暗牌中每个**不同牌种** t（最多 14 种，副露锁定的牌种除外）：`c[t] -= 1` → `computeUkeire` → 汇总。**排序键 `(shanten 升序, totalRemain 降序)`**，并列时保持稳定序（筒→条→字）并全部展示，"推荐"只做排序不做唯一抉择（PRD FR3.4）。

**打后未听牌的选项**（原 P1 提前为 P0）：进张已泛化为"向听数下降的牌"（§4.3），打后一向听手牌的进张列表自动可得，无需额外实现——这正是参考代码框架的优势。

### 4.6 鸣牌（碰/杠）时机建议（meld_advice.dart，P1）

移植参考项目 `_simulate_meld_and_discard`（去掉吃，卡五星无吃）：

```
对手中每种 count ≥ 2 的牌 t：
  模拟碰：暗牌 −2、面子 +1（14→13 张形态）→ 最优切牌 → (向听数, 进张)
  对手中每种 count = 3 的牌 t：模拟杠（补摸 1 张后再评估，或按同向听数放行）
建议条件：碰后向听数 < 当前，或向听数相同且进张 > 当前 → 提示"可碰 X，之后打 Y"
```

输出进 watch 列表：`碰 X → 打 Y（向听 n，进张 m 张）`，供用户在他家打出该牌时快速决策。

### 4.7 剩余张数与已见牌（P1）

`remainCount(t) = 4 − (暗牌[t] + 字牌副露标记贡献(honorMelds 含 t 时 +3) + 场上已见[t])`。

已见牌采用参考项目 `mahjong_state_tracker` 的事件模型：**弃牌 +1、他家碰 +3、他家杠 +4**（自家牌自动计入）。牌池每格实时显示 `剩余/4`；进张排序默认用剩余张数。剩余 0 的进张灰化展示。

### 4.8 性能分析

| 计算 | 规模 | 预估耗时 |
|------|------|----------|
| 单次向听数计算 | 回溯枚举 ≤ 数百分支 | < 50µs |
| 单次胡牌分解枚举 | ≤ 21 雀头 × 每花色 ≤ 9 深度回溯 | < 50µs |
| 进张计算（13 张） | 21 次向听 + 胡牌张做分解 | < 2ms |
| 打牌建议（14 张） | ≤ 14 次进张计算 | < 30ms |
| 每次输入全量重算 | 上述之和 | **< 40ms ≪ 100ms 指标** |

结论：无需 `Isolate`、无需缓存表，主线程同步计算即可；输入事件直接驱动重算（可加 50ms 防抖避免连续点击抖动）。开发期用基准测试固化该结论（§8）。参考项目在 Python 下同类计算亦为毫秒级（见其 `performance_test.py`），Dart AOT 只会更快。

### 8.1 算法单元测试（`test/core/`，v0.2 主战场）

随机手牌生成方法移植自参考项目 `test_efficiency_simulation.py`：21 种 × 4 张 = 84 张牌堆中随机抽 n 张（保证单种 ≤ 4）。

1. **胡牌判定**：
   - 构造性用例：每种面子组合形态（纯顺/纯刻/混合/字牌刻/七对/龙七对…）≥ 30 组正例；反例（差将、差面子、字牌顺子非法、6 张未成两面子等）≥ 20 组；
   - **对拍测试**：独立实现一个暴力枚举器（生成 14 张所有组合逐个判）与主算法对随机采样 10 万组手牌对拍，结果必须一致（这是防回溯剪枝 bug 的关键手段）；
2. **向听数计算**：
   - 定义性用例：已胡 −1、听牌 0、典型一向听/两向听/三向听手牌各 ≥ 5 组（人工推演期望值）；
   - **一致性对拍**：随机手牌上断言 `shanten(h) == 0 ⟺ computeUkeire(h) 存在胡牌张`、`shanten(h) == -1 ⟺ decompose(h14) 非空`；
   - **七对龙定制专项**：含 4 张同牌的手牌，七对向听数必须按"4 张 = 2 对"计算（对照日麻规则会差 1，这是移植 `mahjong` 库公式时的最大陷阱）；
   - 有副露时七对分支必须排除；
3. **进张/听牌计算**：golden 用例——为每个番型 ≥ 1 组"听 X"的定型手牌（如 `4筒6筒 + ...` 听 5 筒为卡五星），人工推演写入期望值；进张张数（含剩余张数扣减）逐一断言；
4. **番型判定**：14 番型逐一正例 + 互斥用例（大三元的牌不得同时计小三元；三龙七对吞并全部低级龙）+ 情境用例（屁胡点炮被拒、杠上开花连乘七对 = 8）；
5. **打牌建议**：经典决策用例（如"打 8 条听两面 5/8 筒"类），验证 `(向听数, 进张)` 排序；
6. **基准测试**：随机 1000 组 14 张输入跑 `rankDiscards`，断言总耗时 < 1s（即单次 < 1ms，留 10 倍余量）。
