# 卡五星听牌器 App · 产品需求说明（PRD）

> 版本：v0.1（2026-08-14）
> 配套文档：[卡五星规则](./卡五星规则.md) · [技术方案](./02-技术方案设计.md) · [开发计划](./03-开发计划.md)

---

## 1. 背景与目标

卡五星是湖北地区流行的三人麻将（筒、条 + 中发白共 84 张，庄家起手 14 张、闲家 13 张，能碰能杠不能吃）。玩家对局中的两个高频决策痛点：

1. **"我听牌了吗？"**——手牌 13 张时，不清楚当前听哪些牌、能胡什么番型；
2. **"打哪张进张最多？"**——手牌 14 张时，靠感觉打牌，经常拆错搭子错过胡牌。

本项目开发一款 **Flutter 单机 Android App**（无账号、无网络依赖、无对局功能），用户手动输入当前手牌后，App 即时计算听牌状态、进张推荐与番型期望，辅助线下对局决策。

### 1.1 产品定位

- **单机工具**，非游戏：不做对局模拟、不做 AI 对手、不做联机；
- **计算正确性是生命线**：听牌/胡牌/番型判定不允许出错；
- **输入要快**：一局中每次轮到自己只有几十秒，输入 + 出结果目标控制在 10 秒内完成常用操作。

### 1.2 目标用户

卡五星玩家（湖北及周边地区），熟悉规则，需要辅助计算而非学规则。

## 2. 核心概念与术语

| 术语 | 定义 |
|------|------|
| 手牌 | 玩家手中未亮出的牌（暗牌） |
| 副露 | 已碰/杠亮出在面前的牌组（碰刻、明杠、暗杠、补杠） |
| 向听数 | 距听牌还差的有效进张数：-1 已胡 / 0 听牌 / n 差 n 张有效牌（未听牌时的量化差距） |
| 听牌（P0 核心） | 向听数 = 0：13 张手牌存在某张牌 x，加入后可构成胡牌结构，称"听 x" |
| 进张 | 能使向听数下降的牌（听牌时即胡牌张）；进张张数 = 各进张牌的剩余张数之和 |
| 胡牌结构 | 1 对将 + 4 组面子（顺子/刻子）；或七对（7 对子，需门清） |
| 番型 | 胡牌的倍数奖励（卡五星 ×2、七对 ×4、龙七对 ×16 等，见规则文档第六章） |
| 已见牌 | 手牌 + 副露 + 其他玩家弃牌/副露中已出现，不可能再摸到的牌 |
| 剩余张数 | 4 − 该牌已见张数（0 张时该进张实际不可进） |

> **重要（2026-08-16 修订）**：卡五星**庄家起手 14 张、闲家 13 张**。因此 App 需支持两种输入场景：13 张（判断听牌）与 14 张（决策打哪张）。

## 3. 功能需求

优先级：P0 = 第一版必须有；P1 = 尽快补充；P2 = 增强，视情况做。

### 3.1 F1 手牌输入（P0）

- **FR1.1** 底部牌池提供全部 21 种牌（1-9 筒、1-9 条、中、发、白）的点选，点一下手牌区 +1 张；
- **FR1.2** 手牌区点击某张牌 −1 张；提供一键清空、撤销（undo，≥10 步）；
- **FR1.3** 每种牌最多 4 张，超出禁止并提示；
- **FR1.4** 手牌数量状态实时显示，并按张数自动推断副露组数：
  - 3n+1 张（13/10/7/4/1）→ 听牌判断模式；
  - 3n+2 张（14/11/8/5/2）→ 打牌建议模式；
  - 徽标同步显示推断结果（如"11 张 · 碰/杠过 1 组"），张数不符 3n+1/3n+2 时给出引导提示；
- **FR1.5** **不录入碰/杠的牌**（简化输入，只录当前手中暗牌）：副露组数由张数自动推断，推断出有副露时七对系列番型自动失效；（P1）**字牌副露标记**：碰/杠了中/发/白时，可用 3 个开关轻量标记，用于补全小三元/大三元判定，未标记时结果区提示"三元番型可能低估"；
- **FR1.6**（P1）已见牌标记：长按牌池中的牌标记场上已见张数（他家弃牌按张 +1、他家碰 +3、他家杠 +4），用于精确计算剩余张数；
- **FR1.7**（P2）手牌快照：自动保存最近 20 次计算的手牌，可一键恢复。

### 3.2 F2 听牌判断（P0 · 核心功能一）

输入 13 张（或 3n+1 张打出一张后）手牌后：

- **FR2.1** 明确给出结论：**已胡 / 听牌 / n 向听**（向听数分级展示，未听牌时量化"差几张有效牌"）；
- **FR2.2** 听牌时列出全部所听牌（可能多张，如同时听 2/5/8 筒），每张牌展示：
  - 牌面；
  - 剩余张数（4 − 已见张数，P1 起结合已见牌标记）；
  - 该牌胡牌后可达成的**所有番型组合及总倍数**（同一张牌可能有多种胡牌分解，列出全部，标注最优）；
  - 需要的前提（如"自摸"才计屁胡、暗四归一需自摸第 4 张）；
- **FR2.3** 展示听牌的牌型结构（将 + 面子分解预览，或七对形态）；
- **FR2.4** 兼容 3n+1 张手牌：先枚举"打任意一张"再判断（即自动降级为打牌建议，见 F3）；
- **FR2.5** 未听牌时展示当前进张列表（使向听数下降的牌及其剩余张数），以及"摸什么能进听"的路径提示（P0；向听 ≥ 2 时仅显示进张，不展开多步路径）。

### 3.3 F3 打牌建议（P0 · 核心功能二）

输入 14 张（或 3n+1 张）手牌后：

- **FR3.1** 枚举"打每一张"后的进张结果，输出推荐列表，排序依据（可切换）：
  - **按（向听数，进张张数）**（默认）：先向听数升序、再进张剩余张数降序；
  - **按进张种数**：所听/所进牌种数；
  - **按番型期望**（P1）：进张张数 × 番型倍数的加权分；
- **FR3.2** 每个候选展示：打哪张 → 打后向听数 → 进张/所听牌列表及各自剩余张数（听牌候选项含番型）；
- **FR3.3** 打后未听牌的候选同样展示进张列表（一向听进张），用户可比较多条进听路径（P0）；
- **FR3.4** 多个候选进张相同时并列展示，把决策留给用户；
- **FR3.5**（P1）排除建议：明确提示"打这张会损失 ×2 番型机会"（如拆掉龙七对潜力）。

### 3.4 F4 番型识别与情境（P0/P1）

- **FR4.1**（P0）听牌结果中的番型判定实现规则文档第六章全部 13 种番型及"不计"互斥；
- **FR4.2**（P0）胡牌情境开关（影响番型与可行性）：
  - 自摸 / 点炮：屁胡只能自摸（默认开，规则可配置）；
  - 刚杠完补牌（杠上开花 ×2）；
  - 他家补杠可抢（抢杠 ×2）；
  - 打出的牌可多家胡（一炮多响提示）；
- **FR4.3**（P1）番型速查表页：完整番型表（倍数、定义、不计），可从听牌结果跳转；
- **FR4.4**（P2）亮倒提示：当前听牌时提示"可亮倒，输赢翻倍"。

### 3.5 F5 规则查询（P1）

- 内置规则文档（基础规则、行牌、番型、结算），分 Tab 展示，支持关键词搜索（番型名）。

### 3.6 F6 设置（P1）

可配置规则项（解决规则文档"待确认事项"导致的地区差异）：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 卡五星番型定义 | 卡张 5 筒（手持 4 筒 + 6 筒，胡 5 筒夹张） | 备选：胡牌含五筒 / 雀头为五筒对；五条卡 5 条是否同样计 |
| 屁胡仅自摸 | 开 | 点炮需有番型 |
| 五条是否可算卡五星 | 关 | 与上项联动 |
| 显示风格 | 剩余张数基于手牌 | P1 起支持已见牌标记 |

### 3.7 F7 碰/杠时机建议（P1）

轮到他家出牌前，App 预计算鸣牌收益（卡五星无吃，仅碰/杠）：

- **FR7.1** 对手中每种 ≥2 张的牌模拟"碰后最优打法"，与不碰对比：向听数下降、或向听数相同但进张更多 → 列入"可碰"提示（含碰后建议打哪张）；
- **FR7.2** 对手中 3 张同牌模拟杠（明杠/暗杠视角区分），展示杠后向听数变化与杠番收益提示（杠本身即时得分 + 杠上开花机会，倍数展示供参考）；
- **FR7.3** 提示不破坏听牌/番型的前提（如"碰后七对作废"自动标注）。

### 3.8 F8 摸打查询表（P2）

13 张待摸状态下，预计算"摸到每一种牌后最优打哪张"的查询表，摸牌瞬间直接给出建议（参考项目 keep_list 概念）。

### 3.9 明确不做（Scope Out）

- 对局/联机/AI 对手/计分记账；
- iOS、桌面端（架构预留跨端能力，但不发布）；
- 拍照识别牌面（P2 之后再评估）。

## 4. 页面与交互流程

### 4.1 页面结构（3 + 1 页；主页布局参考用户提供的同类产品截图：牌池置顶）

```
┌─ 主页（计算器） ─────────────────────────────┐
│ ① 最上：牌池（3 行：筒 9 + 条 9 + 中发白 3）    │
│    每格：牌面 + 已选数角标，点击 +1 加入手牌     │
│ ② 手牌区："已选牌 N 张 · 碰/杠过 m 组"计数徽标  │
│    手牌按点数自动排序，点击 −1；撤销 / 重置按钮  │
│    模式徽标（3n+1·听牌 / 3n+2·打牌建议）        │
│    情境开关（自摸/点炮 · 杠上开花 · 亮倒）        │
│ ③ 结果区：向听数徽标(已胡/听牌/差n张)           │
│    听牌卡片 / 未听进张列表 / 打牌建议(可滚动)     │
│    建议条目格式：打 X → 听 n 张（剩 m）         │
└───────────────────────────────────────┘
辅助页：规则查询页 · 设置页 ·（P2）历史快照页
```

### 4.2 核心流程

1. **听牌判断**：点选 13 张 → 结果区实时出现"✅ 听牌：5筒(×2)、6条(×1)…"；
2. **打牌建议**：点选 14 张 → 结果区出现"推荐打 8 条 → 听 5筒/6筒，共 6 张进张"，点击候选展开详情；
3. **对局中循环**：摸牌（点牌池 +1 → 变 14 张）→ 看建议 → 打牌（点手牌 −1 → 变 13 张）→ 看听牌 → 循环；牌池剩余张数随输入自动更新；
4. **碰/杠时**：手中少牌即可（如碰后剩 12 张、打出后 11 张），App 按张数自动推断副露组数并重算——用户无需任何额外录入操作。

### 4.3 输入效率设计（硬指标）

- 常用一巡操作（摸 1 打 1）≤ 3 次点击；
- 结果计算延迟 < 100ms（体感即时）；
- 手牌排序稳定（筒→条→字，同花色按点数），避免点击错位。

## 5. 非功能需求

| 项目 | 要求 |
|------|------|
| 平台 | Android 8.0+（minSdk 26），竖屏锁定，离线可用 |
| 性能 | 任意输入下计算 < 100ms；冷启动 < 2s |

| 包体 | APK < 20MB（无大型资源依赖） |
| 兼容 | 适配主流分辨率；老年可用性：牌面大、对比度高、支持字体缩放 |

## 6. 边界与异常场景

| 场景 | 处理 |
|------|------|
| 手牌张数 ≠ 3n+1 / 3n+2 | 提示并引导（"碰 1 次后待摸应剩 10 张"等） |
| 某种牌选满 4 张仍点选 | 禁用 + 震动反馈 |
| 推断有副露（张数 < 13/14）时 | 自动排除七对系列番型；结果区提示"三元番型按暗牌计算" |
| 碰/杠了中/发/白但未标记（P1 标记功能） | 三元番型可能低估，结果区给"补充标记"入口 |
| 所听牌剩余 0 张 | 仍显示（灰化 + 标注"已见 4 张，不可进"） |
| 打某张后手牌成 4 张同样的拆分歧义 | 全部分解枚举展示，不做黑盒取舍 |
| 番型配置修改 | 立即重算当前结果，无需重启 |

## 7. 验收标准（第一版 P0 全部满足即验收）

1. 输入任意合法 13 张手牌，向听数与听牌结论和人工推演一致（抽检 ≥ 30 组用例，含七对/龙七对/三元/卡五星用例）；
2. 输入任意合法 14 张手牌，"打每张 → 向听数/进张"计算结果正确且 < 100ms；
3. 13 种番型判定与规则文档第六章一致，互斥"不计"正确；
4. 副露省录模式正确：10/11 张（1 组副露）、7/8 张（2 组）等输入下向听数/进张/番型计算正确，七对系列自动失效；
5. 未听牌手牌正确展示进张列表（含 4 张同牌按"2 对"计入七向听的龙规则定制）；
6. 离线安装即用，无崩溃（Monkey 测试 30 分钟无 ANR/Crash）。
